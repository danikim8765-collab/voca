# 기능 기록서

README는 기능이 **무엇을 하는지** 자세히 적은 설명서예요.
이 문서는 기능이 **왜 있는지**, 그래서 **고쳐도 바뀌면 안 되는 것**이 무엇인지를 적어요.
앱을 계속 고치다 보면 처음 의도가 조금씩 흐려지는데, 그걸 막으려는 기록이에요.

## 쓰는 법

- 기능을 고치기 전에 그 기능의 항목을 먼저 읽어요. '지켜야 할 것'과 어긋나는 수정이면, 고치기 전에 사용자와 먼저 상의해요.
- 기능을 고치면 같은 PR에서 이 문서도 고쳐요. '바뀐 내역'에 날짜와 **이유**를 한 줄 적어요(무엇을 했는지보다 왜 했는지).
- 아직 항목이 없는 기능을 고치면, 그때 항목을 새로 만들어요.
- 항목 모양:

```
## 기능 이름
- 목적: 왜 있는지 (사용자가 겪던 문제)
- 역할: 무엇을 하는지 (짧게. 자세한 건 README)
- 지켜야 할 것: 고쳐도 바뀌면 안 되는 원칙
- 코드: 주로 어디에 있는지
- 바뀐 내역: 날짜 · 이유
```

## 단어 모드 직접 입력 채점 (맞춤법 봐주기)

- **목적:** 뜻을 알고 있는데 폰 자판으로 빨리 치다 생긴 오타 때문에 오답 처리되면 억울하고, 복습 일정도 틀어져요. 시험은 뜻을 아는지 보는 거지 맞춤법 시험이 아니에요.
- **역할:** 앱의 규칙 채점이 먼저 채점해요. 정답이 아니거나 '오타 같음'이면, AI가 켜져 있을 때 AI가 다시 봐요.
- **지켜야 할 것:**
  - 채점 난도(느슨·보통·엄격)는 **뜻을 몇 갈래 써야 하는지만** 정해요. 철자는 어느 난도든 따지지 않아요.
  - 오타는 봐주되, **다른 뜻의 실제 낱말은 오타가 아니에요.** 예: 수입 ↔ 수익, 방해 ↔ 방패, 열정 ↔ 결정, 최고 ↔ 최소, 고대 ↔ 기대. 어미를 뺀 줄기가 흔한 다른 낱말이면 그 낱말을 쓴 걸로 봐요.
  - 어미 안의 오타(포기하디 → 포기하다)는 뜻을 바꾸지 않아서 늘 봐줘요.
  - 오타를 봐주고 맞혔으면 바른 철자를 조용히 보여 줘요. 빨간 '내 답' 표시가 아니라 회색 '철자:' 줄이에요.
- **규칙 채점의 세 단계** (`js/core.js` `nearKo`, `typoKo`):

  | 단계 | 언제 | 처리 |
  |---|---|---|
  | 확실한 오타 | 세 글자 넘는 줄기에서 자모 하나, 또는 어미 안의 오타 | 바로 정답 |
  | 오타 같음 (maybe) | 두 글자 줄기에서 둘째 글자 모음만 다름 (포귀 → 포기, 명학 → 명확) | AI가 되면 AI에게 '오타일 수 있다'고 알려 주고 물음. AI가 안 되면 정답 |
  | 다른 말 | 받침·첫소리가 다름, 첫 글자가 다름 | 오답 (AI가 되면 AI가 다시 봄) |

  maybe를 AI에게 다시 묻는 까닭: 주의 ↔ 주위, 기간 ↔ 기관처럼 모음 하나로 다른 말이 되는 경우가 있어서예요.
- **AI 채점** (`js/ai.js` `SYSTEM`, `STRICT_RULE`, `SPELL_NOTE`):
  - AI는 먼저 학생 답을 오타를 바로잡아 읽고(`read`), 그 말로 채점해요.
  - '철자는 따지지 않는다'는 말을 채점 기준 바로 뒤에 한 번 더 붙여요. 모델이 가까이 있는 기준만 보고 철자까지 엄하게 보는 걸 막으려고요.
- **코드:** `js/core.js` `gradeMeaning`·`typoKo`, `js/ai.js` `aiGradeMeaning`, `js/app.js` `renderMeaningTyping`
- **바뀐 내역:**
  - 2026-11-28 · 두 가지 문제가 있었어요.
    - 규칙 채점이 어미(하다·한)를 떼고 나면 대부분 두 글자 줄기가 남는데, 두 글자 말의 오타는 안 봐주게 돼 있었어요. 그래서 동사·형용사 오타를 거의 못 봐줬어요(명학한, 포귀하다 모두 오답).
    - AI는 채점 기준(보통)을 철자까지 엄하게 보라는 뜻으로 읽어서, 즐거다·줄기다·섦득하다 같은 오타를 오답으로 채점했어요.
    - 그래서 규칙 채점에 오타 세 단계를 넣고, AI가 먼저 오타를 바로잡게 했어요. 예전에 오타라 오답으로 기억해 둔 AI 채점은 버렸어요(`grade.v3`).

## 총정리 단어 문제의 채점 난도

- **목적:** 총정리는 예문·단어 두 모드 문제를 한 학습에서 풀어요. 그런데 예문 모드에서 총정리를 열면 단어 문제가 예문 모드의 채점 설정(기본 '보통')으로 채점돼서, 단어 모드에서 고른 '느슨'이 안 먹었어요.
- **역할:** 학습 계획(과 총정리 홈)의 '총정리 문제 > 단어 채점'에서 느슨·보통·엄격을 고르고, 두 모드와 기기끼리 같이 써요. 고른 적이 없으면 단어 모드의 채점 설정을 따라요.
- **지켜야 할 것:** 총정리를 어느 모드에서 열든 같은 채점이어야 해요.
- **코드:** `js/app.js` `cleanSweepKind`의 `strict`, `sweepStrict`, `gradeStrict`
- **바뀐 내역:** 2026-11-28 · 새로 만듦 (위 문제)

## 총정리 홈

- **목적:** 총정리는 예문·단어 두 모드를 한 학습에서 같이 봐요. 그래서 어느 한 모드의 홈에 있으면 어색했고, 시험 앞의 막판이라는 느낌도 없었어요.
- **역할:** 총정리 기간(목표일 ~ 시험 전날)에만 홈이 셋이 돼요.
  - **총정리 홈(기본):** 오늘 카드(불 색), 총정리 계획(범위·시험·총정리 기간, 문제 방식·먼저 풀 문제·단어 채점), 약한 단어가 있어요. 위 모드 전환은 둘 다 안 눌린 채예요.
  - **예문 홈 · 단어 홈:** 모드 전환을 누르면 가요. 오늘 카드 대신 '총정리 기간이에요' 띠(누르면 총정리 홈)가 있고, 그 모드의 학습 계획 요약·암기 완료·다시 볼 단어·범위 연습이 있어요.
  - 아래 탭과 옆 메뉴의 홈 버튼은 언제나 총정리 홈으로 가요.
- **지켜야 할 것:**
  - 총정리 기간이 아니면 예전 홈 그대로예요.
  - 오늘 몫(총정리·복습)은 총정리 홈에만 있어요. 모드 홈에 같은 걸 또 두면 무엇을 해야 할지 헷갈려서예요.
  - DAY 단독 학습 카드는 모드 홈에서도 보여요.
  - 모드 홈의 역할(c-2)은 사용자가 "일단 해 보라"고 한 단계예요. 써 보고 다시 상의하기로 했어요.

## 날마다 공부량 (쉬기 · 가볍게 · 보통 · 몰아서)

- **목적:** 예전엔 날이 '공부하는 날'과 '쉬는 요일' 둘뿐이었어요. 그래서 "시험 주간 화·수는 가볍게, 영어 전날은 많이" 같은 말을 앱이 담을 수 없었고, 코치가 아무리 알아들어도 할 수 있는 게 없었어요.
- **역할:** 날짜마다 공부량을 정해요. 쉬기 0, 가볍게 0.5, 보통 1, 몰아서 1.5예요.
  - 그날의 새 단어(코치가 켜져 있으면 남은 새 단어를 남은 공부량으로 나눈 몫, 꺼져 있으면 하루 새 단어 수 × 공부량)와 총정리 하루 몫이 이 무게대로 나뉘어요. 정하지 않은 날이 나머지를 나눠 맡아요.
  - '쉬기'로 정한 날은 쉬는 요일과 똑같이 다뤄요.
  - 두 모드가 같이 쓰고, 바꾼 시각(`loadsAt`)으로 기기끼리 맞춰요.
- **지켜야 할 것:**
  - 정한 날이 하나도 없으면 예전 계산과 똑같아야 해요(테스트로 확인).
  - 복습일이 된 단어는 공부량과 상관없이 그대로 나와요. 까먹을 단어를 미루지 않으려고요.
  - 공부량은 코치 카드에서 학생이 누를 때만 바뀌어요.
- **코드:** `js/core.js` `LOADS`·`withLoads`(쉬는 요일 배열에 `.loads`로 붙임)·`dayWeight`·`weightBetween`·`pickBothSweep`, `js/app.js` `setLoads`·`loadsNow`·`restNow`·`coachDaily`·`todayNewTarget`
- **바뀐 내역:** 2026-11-28 · 새로 만듦 (코치 에이전트를 위해)

## 코치 에이전트 (일정 안 비교 카드 · 바로 풀기)

- **목적:** 예전 코치는 정해진 값 네 개(쉬는 요일, 하루 새 단어 수, 총정리 날 수, 오늘 새 단어 수)만 바꿀 수 있어서, 학생 사정에 맞춰 유연하게 상의하지 못했어요. 코치가 사정을 듣고, 안을 몇 가지 내고, 표로 비교하며 같이 정하게 하려는 기능이에요.
- **역할:**
  - AI가 학생 사정에 맞는 안을 1~3개 내요(`options`). 안마다 날짜별 공부량, 시험일 옮기기, 총정리 시작일, 쉬는 요일, 하루 개수, 총정리 날 수, 오늘 개수를 바꿀 수 있어요.
  - 앱이 안마다 날짜별 양을 계산해(`dayForecast`) 카드로 보여 줘요. 안 탭, 날짜 칸(진할수록 많이 하는 날, 바뀌는 날은 주황 테두리), 모두 몇 문제·약 몇 분, 바뀌는 것, 코치의 까닭이 있어요.
  - '조금 바꿀래요'를 누르고 날짜를 누르면 그날 공부량을 고칠 수 있고, 숫자가 바로 다시 계산돼요.
  - '이렇게 할게요'를 눌러야 바뀌어요. 바꾼 줄에 '되돌리기'가 있어요.
  - AI가 지금 풀어 보자고 하면(`quiz`) [시작] 카드가 떠요: 약한 단어, 다시 볼 단어, 오늘의 복습, 코치가 고른 단어.
  - AI는 오늘부터 시험 뒤 한 주까지의 달력(`calendarText`: 날마다 무엇을 얼마나, 정해 둔 공부량)을 보고 날짜를 정해요.
- **지켜야 할 것:**
  - 계산은 언제나 앱이 해요. AI가 짐작한 숫자가 든 문장은 버려요(`numbersOk`).
  - 학생이 누르기 전엔 아무것도 안 바뀌어요.
  - 바뀌는 것은 카드에 다 보여야 해요(시험일을 옮기면 '12월 7일 → 12월 11일'처럼).
  - 시험 주간에 실제 영어 시험이 뒤쪽이면, 시험일을 영어 시험날로 옮기고 다른 과목 시험 날은 가볍게 하는 안을 내요. 사용자가 처음 말한 상황이에요.
  - 예전 값 네 개만 바꾸는 안 하나는 예전 카드(남는 단어를 어디 붙일지 고르기가 있음)로 보여 줘요.
- **날짜는 앱이 정해요:** AI는 날짜를 셈하지 않고 `<calendar>`에 적힌 "다음 주 목" 같은 주·요일 표시를 그대로 써요. 앱이 그걸 날짜로 바꿔요(`dayFromLabel`, 한 주는 월요일부터). 무료 모델이 "목요일"을 화요일 날짜로 쓰는 일이 있어서 이렇게 했어요.
- **AI 모델에 따라 다름:** 2026-11-28 무료 Groq(gpt-oss-120b)로 시험한 결과예요.
  - "목요일은 조금만" → 맞게 냈어요(다음 주 목 가볍게).
  - "다음 주 수~금 수학여행" → 쉬기로는 맞게 했지만 한 주 늦은 날짜를 골랐어요.
  - 사용자가 처음 말한 시험 주간 상황 → 이번 주 화~목을 가볍게 하고 시험일은 그대로 두는, 틀린 안을 냈어요.
  - 그래서 코치용 AI는 Gemini·Claude를 권해요(여기선 키가 없어 시험하지 못했어요).
  - 어느 모델이든 카드에서 날짜가 다 보이고 누르기 전엔 안 바뀌니, 틀린 날은 '조금 바꿀래요'로 고치면 돼요.

## 계정 로그인 (아이디·비밀번호 · 초대 코드)

- **목적:**
  - 예전 동기화는 GitHub 토큰을 기기마다 붙여 넣어야 해서 번거로웠어요.
  - 친구들은 GitHub 계정도 없고 토큰도 어려워요.
  - 아이디·비밀번호로 로그인하면 그 계정 진도로 맞춰지게 하려는 기능이에요. 친구들도 각자 계정을 써요.
- **역할:**
  - 앱(설정 > 연결)에서 회원가입(아이디·이름·비밀번호·초대 코드), 로그인, 로그아웃, 비밀번호 찾기(복구 코드), 비밀번호 바꾸기, 계정 지우기를 해요.
  - 동기화 엔진(`js/sync.js`)은 그대로 쓰고, 저장하는 곳만 GitHub Gist 대신 계정 서버예요.
  - 서버는 Cloudflare Workers + D1이고 무료예요. 컴퓨터를 켜 둘 필요가 없어요.
- **지켜야 할 것:**
  - 비밀번호 원문은 서버에 보내지 않아요(앱이 PBKDF2로 바꾼 값만).
  - 토큰과 복구 코드는 서버에 해시로만 저장해요.
  - 초대 코드가 있어야 가입되고, 사람 수 한도(`MAX_USERS`)가 있어요. 무료 한도를 지키고 모르는 사람이 못 쓰게 하려고요.
  - 로그아웃이나 계정 지우기를 해도 이 기기의 진도는 남아요.
  - 한 기기에서 다른 계정으로 로그인하면 진도를 합칠지 지울지 꼭 물어봐요. 친구 진도와 섞이면 안 돼요.
  - 합치는 방법은 GitHub 동기화와 똑같아요(`core.js`). 서버는 저장만 해요.
  - 서버를 고칠 땐 이미 퍼진 예전 앱의 요청도 계속 받게 해요. 앱보다 서버가 먼저 바뀌어서예요.
  - 코치가 부를 이름은 가입 이름과 따로, 코치 탭에서 물어요(사용자가 정함).
- **사용자와 정한 것 (2026-11-28):**
  - 친구도 써요.
  - 아이디·비밀번호에 이름도 적어요.
  - 초대 코드를 둬요.
  - 동기화는 계정 하나로 해요. GitHub는 '예전 방식'으로 남겨 두고 '계정으로 옮기기'를 둬요.
- **코드:**
  - 서버: `server/worker.js`·`schema.sql`·`README.md`(설정 순서)
  - 앱: `js/account.js`, `js/sync.js`(`kind: 'account'`), `js/app.js` `openAccount`·`useAccount`·`renderSyncStatus`
  - 테스트: `tests/server.test.mjs`·`account.test.mjs`
- **바뀐 내역:** 2026-11-28 · 새로 만들고 Cloudflare에 올림. 주소 `https://voca-account.lexioative.workers.dev`(Worker `voca-account`, D1 `voca`), 앱 주소 `ORIGINS`는 GitHub Pages, 초대 코드 `INVITE`는 Cloudflare 비밀 값으로 사용자가 정함. 실제 서버에서 가입·파일 올리기/받기·틀린 비밀번호·계정 지우기를 시험함.
  - 2026-11-28 · 사용자 요청으로 계정 동기화는 문제를 풀 때마다(1.5초 모아서). 예전 15초 간격은 GitHub 쓰기 한도(시간당 500번) 때문이었는데 계정 서버는 하루 10만 번이라 넉넉해서. 대신 폰 데이터를 아끼려고 바뀐 파일만 받고(`?have=`) 올릴 땐 gzip(`X-Body-Gzip`). 서버는 예전 앱 요청도 그대로 받음
  - 2026-11-28 · 사용자 요청: 계정을 설정에서 떼어 '계정' 화면으로(홈 위 사람 단추, 탭은 안 늘림 — 아래 바가 비좁아져서). 처음 열면 계정 화면부터, '로그인 없이 쓰기'도 둠(로그인 안 하던 사람·인터넷이 없을 때 막히지 않게). '로그인 상태 유지'를 끄면 앱을 다시 열 때 로그아웃

## 테마 · 화면 꾸미기 (설정 > 화면)

- **목적:**
  - 꾸미기 고르기(강조 색 5가지를 모드마다, 모서리, 카드, 퀴즈 바탕)가 너무 많아서 설정이 난잡했어요. 하나하나 고르기보다, 잘 맞춰 둔 모습 몇 개 중에 고르는 게 낫다는 생각이에요.
  - 늘 같은 모습이면 질리니까 분위기가 확 다른 테마를 하나 더 둬요(밤에 공부할 때 신나는 네온).
- **역할:**
  - 테마 두 개: **오리지널**(지금까지의 모습, 밝게·어둡게)과 **네온**(늘 어둡게). 처음엔 오리지널.
  - 테마 말고 남은 꾸미기: 밝기(오리지널만), 글자 크기, 예문 글꼴, 홈에 보일 것, 정답 반응, 앱 키보드 높이·소리.
- **지켜야 할 것:**
  - 테마는 색·빛만 바꿔요. 화면 구성, 글자 크기, 버튼 위치는 두 테마가 같아요(하나만 고치면 다른 쪽이 깨지지 않게, 어느 테마에서도 익숙하게).
  - 오리지널의 홈 화면 모습은 사용자가 마음에 들어 하는 모습이라 그대로 둬요.
  - 네온의 빛은 누를 것과 중요한 숫자에만. 예문·뜻처럼 읽는 글엔 빛을 넣지 않아요(오래 읽어도 눈이 편하게).
  - 네온도 모드마다 색이 달라요(예문 하늘·보라, 단어 분홍·주황). 모드를 바꾸면 바로 보이게.
  - 폰·패드·컴퓨터(왼쪽 메뉴, 두 칸 홈) 모두에서 봐요.
  - 형광펜의 네온 모습(블랙라이트 형광 노랑)은 **내가 칠한 단어와 형광펜 버튼에만**. 해석 속 뜻 강조(`.ko-mark`)는 매 문제 읽는 글이라 빛을 넣지 않아요.
  - 정답 시트의 계속하기는 열릴 때부터 또렷하게 보여야 해요(바로 누를 수 있게). 깜빡이는 건 빛뿐이고, '차분하게'·움직임 줄이기에선 안 깜빡여요.
  - 테마를 고르면 첫 화면부터 그 테마로(깜빡임 없이, `js/look.js`가 `<head>`에서).
- **사용자와 정한 것 (2026-11-28):**
  - 테마는 오리지널 · 네온 둘. 기본은 오리지널.
  - 강조 색은 없앰. 예전에 다른 색을 골라 둔 사람도 테마 색으로 돌아가도 괜찮음.
  - 네온은 시안(빛 세기·색·오늘 카드 테두리) 그대로.
  - (같은 날 사용자 요청) 네온의 '계속하기'는 꽉 채운 버튼 대신 빛나는 관, 형광펜은 네온만의 모습, 설정의 테마 미리보기는 예문·단어 모드마다 그 모드 색으로.
- **코드:** `js/look.js`(`skin`), `style.css` 맨 끝 `:root[data-skin="neon"]` 블록 · `.skin-pick`, `index.html` `#set-screen`, `js/app.js` `renderLook`. 테스트 `tests/look.test.mjs`
- **바뀐 내역:** 2026-11-28 · 사용자 요청으로 네온 테마를 만들고 강조 색·모서리·카드·퀴즈 바탕 고르기를 없앰(설정이 난잡해서). 실제 앱 화면(폰·패드·컴퓨터, 두 모드)을 찍어 비교하며 같이 정함. 오리지널 화면은 바뀌기 전과 같은지 사진으로 견줘 봄
  - 2026-11-28 · 사용자 요청: 네온의 계속하기를 오늘 카드와 같은 빛나는 관으로(시트가 열릴 때 네온사인처럼 빛이 깜빡이며 켜짐), 형광펜은 블랙라이트에 빛나는 형광 노랑(모드 색과 안 겹치게), 테마 미리보기는 모드마다 그 모드 모습으로. 네온에서 화면 제목이 다 빛나던 걸 홈·계정의 VOCA만 빛나게(어디가 중요한지 흐려져서)
